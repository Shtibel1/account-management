# Extraction Agent Manifest

## Role & Objective
The Extraction Agent maps, parses, and cleans unstructured invoice text into a rigidly typed JSON structure (`ExtractedData`). 

Instead of performing raw image vision analysis as its primary mechanism, it consumes the `rawOcrText` generated by the Preprocessor. It uses the LLM's advanced language understanding to find semantic keys (supplier name, VAT ID, invoice number, dates, amounts) in bilingual, mixed RTL text.

## Fallback and Vision Capabilities
If the deterministic validation layer fails (e.g. mathematical check fails, or data fields are missing) and a retry is triggered, the Extraction Agent can consume the raw `fileUrl` (Vision capabilities) as a fallback. This allows visual re-inspection of the original document layout to resolve complex spatial ambiguities or parsing errors.

## Input/Output Contract

### Input Context
- `rawOcrText`: `string` (Plain text OCR string to parse)
- `fileUrl`: `string` (Fallback signed URL for multimodal visual re-inspection)
- `mimeType`: `string` (Fallback MIME type for visual re-inspection)
- `useVisionFallback`: `boolean` (If true, LLM will inspect the document visually alongside the OCR text)
- `withRetryHint`: `boolean` (If true, directs the agent to correct previous arithmetic or field errors)

### Output Interface (`ExtractedData`)
```typescript
export interface FieldBbox {
  x1: number;
  y1: number;
  x2: number;
  y2: number;
}

export interface ExtractedData {
  supplier_name: string | null;
  supplier_vat_id: string | null;
  invoice_number: string | null;
  invoice_date: string | null;        // Format: YYYY-MM-DD
  amount_before_vat: number | null;
  vat_amount: number | null;
  total_amount: number | null;
  expense_category: string | null;
  bboxes?: {
    supplier_name?: FieldBbox;
    supplier_vat_id?: FieldBbox;
    invoice_number?: FieldBbox;
    invoice_date?: FieldBbox;
    amount_before_vat?: FieldBbox;
    vat_amount?: FieldBbox;
    total_amount?: FieldBbox;
    expense_category?: FieldBbox;
  };
}
```

### Cumulative Cost Metrics
Each time the Extraction Agent calls the LLM, it must log usage metrics to the shared LangGraph State:
- `costMetrics.inputTokens`: Increments by the LLM input tokens consumed.
- `costMetrics.outputTokens`: Increments by the LLM output tokens consumed.

## Guardrails
- **Null Values Rule:**
  - If a specific field is not found in the text (or image fallback), return `null` instead of generating dummy values.
- **Normalization:**
  - **Dates:** Convert standard formats (e.g., `DD/MM/YYYY`, `DD.MM.YY`) to `YYYY-MM-DD`.
  - **Amounts:** Clean currency symbols and separators, parsing into floats.
  - **VAT ID:** Strip hyphens, spaces, and country codes to output 9 numeric digits.
- **Bilingual & Layout Challenges:**
  - You will receive raw OCR text from bilingual Israeli invoices. The text may have mixed RTL/LTR layout strings where numbers and labels are inverted. Use proximity and semantic context to reconstruct the correct connections (e.g., matching the word 'סה"כ' with the nearby floating number).
- **Retry Guidance:**
  - On retry (`withRetryHint: true`), the agent must inspect the previous failed values and look for alternative interpretations of the text/layout.
